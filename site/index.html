How testing works
1
Prompt
A single Markdown file with a stated contract: named inputs, and what the output must always and never do.
2
Eval cases
Cases that assert against that contract, including missing, contradictory, and adversarial input.
3
Badge
CI runs the cases on every pull request. The badge on each card is that run, not a claim.
Notifications
An email when something new is shelved.
One short note per acquisition: what it does, what it was tested against. No digests, no roundups.
Delivered through reemthewriter.substack.com. Unsubscribe any time.
